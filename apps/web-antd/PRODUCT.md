## Platform

web

## Users

内部销售/业务员，在日常办公场景中使用（办公室、客户拜访前后）。他们需要在较短时间内完成报价单的创建、修改、查询与跟进，对界面学习成本敏感，但更在意操作效率与数据准确性。

其他已确认受众（按角色分工，非主用户）：

- **运营/订舱/采购**：维护内部费率库（卡车、海运、熏蒸等成本表）与模板
- **管理员**（`super_admin` / `admin`）：组织架构、用户、角色、操作日志、系统公告

## Product Purpose

福瑞多报价系统是一套面向内部销售的 B2B 报价管理后台，帮助业务员快速生成、维护并向客户交付报价方案。

成功标准：减少重复录入、降低报价出错率、缩短从询价到出单的周期，让销售把精力放在客户沟通而非系统操作上。

## Positioning

**内部费率库 + 引用 + 快照 + 状态机** 四支柱架构：成本侧单一数据源，报价行引用成本并固化快照，成本改价不自动改写已发出报价；草稿可改、发出后冻结。这是与「Excel 拼表」或「无快照的简易 CRM 报价」的本质差异。详见 [QUOTE.md](./QUOTE.md)。

## Operating Context

- **部署形态**：公司内部 Web 后台（Vue Vben Admin monorepo 子应用 `apps/web-antd` + Spring Boot API `quote-api`）
- **典型工作流**：维护主数据与费率库 → 建报价（草稿）→ 从库引用成本 → 写入快照 → 提交/审批/发出 → 赢单/丢单/过期
- **协作边界**：销售只读引用费率库；运营维护成本；管理员配置权限与全员公告
- **语言**：中英双语 i18n（`zh-CN` / `en-US`）

### 技术约束

- 前端：Vue 3 + Vite + Ant Design Vue + Vben 5.x（`@vben/web-antd`）
- 后端 API：REST，`quote-api`（PostgreSQL `frd_postgres`）
- 权限：路由级 `authority` + 后端 AUTHZ（见 `quote-api/docs/AUTHZ.md`）
- 报价核心约束：引用可追溯、快照不可被成本库静默覆盖、状态驱动操作边界

### 术语

- **内部费率库**：`cost_road` / `cost_sea` / `cost_rail` / 熏蒸等成本表

- **快照**：引用时刻固化的价格
- **报价规则**：主数据中可配置的报价业务规则提示

## Product Principles

1. **效率优先**：高频操作（新建报价、复制历史单、改价、导出）路径要短，减少点击层级。
2. **数据可信**：金额、数量、折扣等关键数字必须清晰可读；状态与版本一目了然；快照保护已发出报价。
3. **单一成本真相**：费率库是成本侧唯一数据源；报价通过引用 + 快照与之解耦。
4. **一致可预期**：扩展功能时沿用既有列表/表单/Sheet 交互模式，降低学习成本。
5. **克制装饰**：反馈与引导优先；不做与任务无关的视觉表演（细节规范见 DESIGN.md）。
